## 🎯 왜 만들었나

2026년 창업·소상공인 지원 통합공고 기준으로 **111개 기관이 508개 사업에 3조 4,645억 원**을 씁니다. 그런데 사장님들은 자기가 받을 수 있는 게 뭔지 모릅니다.

- 공고는 부처·지자체 사이트에 흩어져 있고, 자격 조건은 공고문 안 표 속 문장으로만 적혀 있습니다.
- 매출·업력·근로자 수·신용등급을 상품마다 손으로 대조해야 합니다.
- 신청 서류는 대부분 HWP 서식이고, 도장 하나 빠져서 반려되면 다음 공고까지 기다려야 합니다.
- 지원금과 대출을 어떻게 섞어야 부족한 금액을 채울 수 있는지 계산해 주는 곳이 없습니다.

**소비**는 사업자 인증과 마이데이터 연동 한 번으로 이 과정을 대신합니다. 자격을 판정하고, 부족한 금액을 조합해 주고, 서류를 채워 검증하고, 실행된 대출의 상환까지 따라갑니다.

## ✨ 주요 기능

### 1. 자격 판정 — 지금 받을 수 있는지 3분 안에

사업자 인증과 마이데이터 연동이 끝나면 대출·지원사업 전체를 한 번에 판정합니다.

- **대출** : 신용등급·업력·근로자 수·매출을 상품 요건과 정량 비교합니다. `가능 / 불가` 두 가지로 확정됩니다.
- **지원사업** : 공고문을 LLM이 읽어 판정합니다. 지역·업종·매출처럼 숫자로 떨어지는 조건은 SQL 필터로, 시군구·1인 사업장처럼 문장을 읽어야 하는 조건은 LLM이 맡습니다. 사람이 직접 확인해야 하는 조건(여성기업·백년소상공인 지정 등)은 `확인 필요`로 따로 알려 드립니다.
- 판정 결과는 상품 목록의 배지 색으로 바로 읽힙니다 — 가능 / 확인 필요 / 불가.

### 2. 자연어 검색 — "키오스크 지원금"이라고 치면 찾아줍니다

공고 제목이 아니라 **본문 의미**로 검색합니다. KoE5 임베딩 + pgvector 벡터 검색이라 LLM을 부르지 않고 1초 안에 돌아옵니다.

### 3. 자금 조합 — 부족한 금액은 조합으로

목표 금액을 넣으면 **무상 지원금을 먼저 채우고 남는 금액만 대출로** 구성한 조합을 여러 개 만들어 줍니다.

- 조합마다 평균 금리·월 상환액(36개월 기준)을 나란히 비교
- 조합을 고르면 포함된 상품 전부를 한 번에 신청 시작

### 4. 서류 — 자동으로 채우고, 제출 전에 검증

**초안 작성 (Document Agent)**
HWP·HWPX·DOC·DOCX 신청서 서식을 분석해 채울 칸을 뽑아내고, 사용자 정보·사업자 정보·마이데이터에서 값을 끌어와 초안을 만들어 드립니다. 다운로드해서 도장만 찍으면 됩니다.

**제출 서류 검증 (OCR)**
사업자등록증·납세증명서·통장사본 등을 업로드하면 즉시 확인합니다.

- 이 사용자의 서류가 맞는가 (대표자명·사업자번호 대조)
- 서류 종류가 맞는가
- 도장·서명·발급일자가 있는가
- 유효기간이 지나지 않았는가

기관에서 반려될 사유를 제출 전에 잡습니다.

### 5. 신청 현황 — 어디까지 왔는지 한 화면에

준비 중 → 신청 완료 → 심사 중 → 승인/선정 → 실행/지급 완료. 대출과 지원사업을 한 목록에서 보고, 준비 중인 신청서는 바로 이어서 작성합니다.

### 6. 상환 관리 — 실행된 대출을 끝까지

SSAFY 금융망과 연동해 실행된 대출의 잔액·다음 상환액·남은 회차·자동이체 기록을 보여 줍니다. 한 번에 갚을 때 아끼는 이자를 계산해 주고, 완납도 여기서 합니다.

### 7. 상권 분석 — 창업할 동네를 숫자로

희망 업종과 동을 고르면 서울시 상권 데이터로 그 자리를 진단합니다.

- 동종 업종 점포 수·밀도와 서울 평균 비교
- 점포당 월 매출 추정, 요일·성별 매출 구조
- 개업·폐업 추이, 서울 내 순위, 인접 동 비교

**사업자 인증 없이도 쓸 수 있는 유일한 분석 기능**입니다. 예비창업자가 여기서 시작합니다.

### 8. 대시보드 — 사장님의 오늘

- 사업 스냅샷 : 매출 추이, 업력, 근로자 수, 세액
- **의무보험 체크리스트** : 업종별로 가입해야 하는 4대보험·배상책임보험을 마이데이터와 대조해 `가입 완료 / 확인 필요 / 가입 필요 / 가입 제외`로 짚어 줍니다.
- 판정 요약, 신청 가능한 대출·지원사업, 상환 예정 금액

### 9. 예비창업자 모드

사업자등록 전이어도 회원가입만 하면 상권 분석과 예비창업자 대상 지원사업·대출 탐색이 열립니다. 사업자 인증이 필요한 기능은 화면 안에서 "사업자 인증하기"로 안내합니다.

### 그 외

- 구글 소셜 로그인 / 계정 연결
- 휴대폰 본인확인, 사업자 진위확인
- 관심 목록(북마크), 알림, 마이데이터 계좌 조회

```
                        ┌──────────────────────────────────────────────┐
  브라우저 ──HTTPS──▶  │ Nginx                                        │
                        │  /            → frontend (React, 정적 파일)  │
                        │  /api/**      → backend  (Spring Boot :8080) │
                        └───────────────────┬──────────────────────────┘
                                            │
                    ┌───────────────────────┼─────────────────────────┐
                    ▼                       ▼                         ▼
           ┌──────────────┐        ┌──────────────┐          ┌──────────────┐
           │  PostgreSQL  │◀──────▶│   Backend    │─────────▶│   AI 서버    │
           │  + pgvector  │        │ Spring Boot  │  HTTP    │   FastAPI    │
           └──────────────┘        └──────┬───────┘          └──────┬───────┘
                    ▲                     │                         │
           ┌──────────────┐               │                  ┌──────┴───────┐
           │    Redis     │◀──────────────┤                  │ KoE5 · OCR   │
           │ 세션·토큰    │               │                  │ Document     │
           └──────────────┘               │                  │ Agent        │
                                          ▼                  └──────┬───────┘
                        ┌─────────────────────────────┐             │
                        │ SSAFY 금융망 · Google OAuth  │             ▼
                        │ 마이데이터(국세·4대보험)     │        GMS (LLM)
                        └─────────────────────────────┘
```

- **Backend**가 모든 비즈니스 로직과 외부 연동(금융망·OAuth·마이데이터)을 맡습니다. 프론트는 AI 서버를 직접 부르지 않습니다.
- **AI 서버**는 DB에서 공고 벡터만 읽고, 사용자 데이터는 백엔드가 요청에 담아 보냅니다. 판정·검증 결과도 백엔드가 저장합니다.
- **공고 적재 파이프라인**(파싱 → 조건 추출 → 청킹 → 임베딩)은 서버 이미지와 별개로 EC2 밖에서 배치로 돕니다.

## 🤖 AI 파이프라인

### 지원사업 자격 판정

```
기업마당 공고 222건
   │  MinerU(PDF, OCR 모드) · hwp5html(HWP) · XML 파싱(HWPX)
   ▼
본문 텍스트 ─▶ 조건 추출(LLM) ─▶ program_condition (지역·업종·매출·업력·근로자 수)
   │
   └─▶ 350토큰 청킹 ─▶ KoE5 임베딩(1024차원) ─▶ program_chunk (pgvector)

사용자 프로필 ─▶ ① SQL 정형 필터 (시도 · 소상공인 규모 · 매출 상한 · 업력)
               ─▶ ② 후보 전량 LLM 검증 (시군구 · 1인 사업장 · 문장형 조건)
               ─▶ eligible / unknown / ineligible + 확인 항목
```

- 정형 필터 도입 후 검색 Recall@30 **0.368 → 0.947**, 후보 전량 검증 후 **포함률 1.0**
- 판정 범위를 "가진 정보로 대조할 수 있는 조건"으로 재정의해 판정 정확도 **0.478 → 0.826**
- 근거 문서 : `ai/docs/03_baseline.md`, `ai/docs/04_judgement_design.md`

### 제출 서류 검증 (OCR)

```
업로드 파일(PDF·JPG·PNG) ─▶ PP-OCRv5 ─▶ 텍스트 ─▶ GMS 파서(JSON 강제)
                                                    │
백엔드가 보낸 정답값(대표자명·사업자번호·서류명) ──▶ 대조 ─▶ 통과 / 실패 + 사유
```

- 대출 서류 4종 · 지원사업 서류 4종, 본인/타인/종류 불일치 16개 시나리오 통과
- 계약 문서 : `ai/docs/05_ocr_contract.md`

### 신청서 초안 작성 (Document Agent)

```
HWP/DOC ─▶ hwp2hwpx · LibreOffice ─▶ HWPX/DOCX ─▶ 구조 파싱 ─▶ 채울 칸 후보 추출
                                                                    │
USER · BUSINESS · MYDATA · PROGRAM 소스에서 값 resolve ────────────▶ 초안 문서 생성 ─▶ 다운로드
```

- 진행 기록 : `docs/document-agent-progress.md`
