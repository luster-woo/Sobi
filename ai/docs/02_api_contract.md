# RAG 추천 API 계약

AI 서버가 제공하는 맞춤 지원사업 추천 API. 담당: RAG 파트.

기준일 2026-09-15. 변경 시 이 문서를 먼저 고치고 알립니다.

## POST /rag/recommend

사업자 프로필로 신청 가능한 지원사업을 찾고, 각 공고의 자격 요건을 검증해
돌려줍니다. **외부에서 쓸 엔드포인트는 이것 하나입니다.**

### 요청

```json
{
  "region": "경북",
  "address": "경상북도 안동시 경동로 456",
  "business_code": "CS100005",
  "employee_count": 2,
  "open_date": "2024-06-03",
  "annual_revenue": 180000000
}
```

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `region` | string | O | 시도. 아래 16개 표준 표기 중 하나 |
| `address` | string | O | 전체 주소. 시군구·읍면동 조건 대조에 씁니다 |
| `business_code` | string | O | CS 업종 소분류 코드. `minor_code.code` |
| `employee_count` | int | O | 상시근로자 수 |
| `open_date` | date | O | 개업일 `YYYY-MM-DD` |
| `annual_revenue` | int | X | 연매출(원). 없으면 매출 조건을 통과 처리 |

**시도 표준 표기 16개** — 전남과 광주는 `전남광주` 하나로 통합합니다.

```
서울 부산 대구 인천 대전 울산 세종 경기 강원
충북 충남 전북 전남광주 경북 경남 제주
```

`address`가 필요한 이유: 공고에는 "안동시 관내", "봉화군 소재" 같은 시군구·읍면동
조건이 흔한데 `region`(시도)만으로는 판정할 수 없습니다. 시도가 같고 시군구가
다른 공고를 걸러내는 것이 이 API의 핵심 기능 중 하나입니다.

### 응답

```json
{
  "query": "경상북도 안동시에서 제과점을 운영하는 소상공인. 업력 2년 3개월, ...",
  "results": [
    {
      "program_id": 2,
      "pblanc_id": "PBLN_000000000121646",
      "title": "[경북] 안동시 2026년 소상공인 카드수수료 지원사업 참여점포 모집 공고",
      "distance": 0.5328,
      "status": "eligible",
      "reason": "사업자 소재지가 안동시이며 연매출 4억원 이하로 필수 조건을 충족함",
      "check_items": ["전년도(2025년) 연매출액 확인 필요"]
    }
  ]
}
```

| 필드 | 설명 |
|---|---|
| `query` | 프로필로 만든 검색 질의문. 디버깅용이며 화면에 노출하지 않아도 됩니다 |
| `program_id` | `support_program.id` |
| `pblanc_id` | 기업마당 공고 ID |
| `distance` | 코사인 거리. **0에 가까울수록 유사**합니다. 0~2 범위 |
| `status` | `eligible` · `ineligible` · `unknown` |
| `reason` | 판정 사유 한 문장 |
| `check_items` | 신청 전 사업자가 직접 확인해야 할 항목. 없으면 빈 배열 |

`results` 는 `distance` 오름차순입니다. `status` 로 정렬돼 있지 않으므로
화면에서 자격 있는 것부터 보여주려면 클라이언트가 다시 정렬하세요.

### status 세 값

| 값 | 의미 | 화면 처리 제안 |
|---|---|---|
| `eligible` | 필수 조건을 모두 충족한다고 확인됨 | 추천 목록에 노출 |
| `ineligible` | 필수 조건 중 하나 이상이 명확히 어긋남 | 숨기거나 접어둠 |
| `unknown` | 확인할 수 없는 필수 조건이 있음 | "조건 확인 필요"로 노출 |

`unknown` 이 나오는 전형적인 경우는 우리가 받는 프로필로는 알 수 없는 조건들입니다.
대표자 연령·성별, 신용점수, 대출·보험 가입 여부, 매출 감소율, 휴폐업·체납 여부,
중복 수혜 이력 등. **`unknown` 을 탈락으로 처리하지 마세요.** 실제로는 자격이 되는
경우가 많고, 확인은 사업자 본인이 해야 합니다.

## POST /rag/search

검색 단계만 수행합니다(LLM 검증 없음). 요청 형식은 `/rag/recommend` 와 같습니다.

**내부 디버깅·평가 전용입니다.** 벡터 검색이 잘못 물어온 것인지 LLM 판정이
틀린 것인지 구분할 때, 그리고 Recall 측정에 씁니다. 외부에서 호출하지 마세요.

## 에러

| 상황 | 현재 동작 | 예정 |
|---|---|---|
| 없는 `business_code` | 500 | 400 + 메시지 |
| `region` 표기 오류 | 조건에 안 걸려 결과 부실 | 400 |
| GMS 호출 실패 | 전 건 `status: "unknown"` | 유지 |
| 검색 결과 0건 | `results: []` | 유지 |

에러 응답 정형화는 아직입니다. 우선순위 필요하면 알려주세요.

## 아직 임시인 부분

* 현재 검색은 상위 청크 30개 → 공고 최대 10건으로 제한합니다. 목표는
  "자격 되는 공고를 빠짐없이" 이므로, 정형 필터 통과분 전체를 검증하는 구조로
  바꿀 예정입니다. 공고 222건 적재 후 진행합니다
* 공고 본문 파싱 전이라 현재 DB에는 확인용 5건만 들어 있습니다
