`04_judgement_design.md`.

## 한눈에

| 날짜 | 무엇을 했나 | 검색 | 판정 |
|---|---|---|---|
| 09-15 | 본문 파싱·고정 청킹·적재 | Recall@30 0.368 | — |
| 09-15 | 조건 추출 → 정형 필터 가동 | **0.947** | — |

## 09-15 · 파싱과 적재

### PDF 파서 — MinerU `-m ocr` 전건 적용

`auto` 모드는 텍스트 레이어가 있으면 그대로 쓰는데, hwp→pdf 변환물은
그 레이어가 망가져 있다.

```
auto: □ ( )지원대상 ’25년도 연매출액이 억 원 이하3 이며
ocr : (지원대상) '25년도 연매출액이 3억 원 이하이며, 사업자등록증 상의
      소재지가 봉화군인 소상공인
```

6페이지 기준 32초 대 36초라 비용 차가 작고, 정상 PDF도 MinerU가 이미
OCR을 태우고 있었다. 전건 `-m ocr`로 통일했다.

**리소스** — CPU 7초/페이지·피크 6.3GB, GPU(RTX 4050) 1.5~2초/페이지.
104건 913페이지가 CPU 2시간 30분 / GPU 14분. EC2 15GiB에서 AI 서버(~4GB)와
동시 실행하면 여유가 3GB뿐이라 별도 머신을 권한다.

### 파싱 결과 214/222

| 포맷 | 성공 | 평균 |
|---|---|---|
| pdf | 104/104 | 12,448자 |
| hwp | 85/86 | 13,970자 |
| hwpx | 25/25 | 10,512자 |

나머지 8건(이미지 6·docx 1·`117948` 문서속성 손상)은 API 사업개요로 대체.

### 청킹 — fixed 350토큰 / 겹침 50

214건 → 5,409청크. 문서당 25.3개, 96%가 350~399토큰, 512 초과 0건.

**약점은 표가 중간에서 잘리는 것.** "연매출액 4억원 이하"라는 자격 조건이
깨진 `<table>` 안에 걸린 사례가 있다. 구조 기반 청킹과 비교할 근거로 남긴다.

### 검색 평가 — 순수 벡터 0.368

| 지표 | 값 | 참고: 사업개요만 |
|---|---|---|
| Recall@10 (전국 제외) | 0.316 | 0.368 |
| Recall@30 (전국 제외) | 0.368 | 0.579 |

본문 전체를 넣은 결과가 사업개요 한 줄만 쓴 것보다 나아지지 않았다.

정답 순위를 222건 전체에 매겨보면 분포가 둘로 갈린다.

```
중앙값 66위 / 최고 1위 / 최저 162위
   1~10위  ###### 6     ← 지역·업종이 공고문에 명시된 경우
  11~30위  # 1
  31~60위  ## 2
 61~100위  ##### 5      ← 매칭할 근거가 아예 없는 경우
 101위 이하 ##### 5
```

P01(서울 마포 한식)의 정답이 **162위**다. "소담스퀘어 in 부산 제품사진 촬영"은
지역 제한이 없어 자격은 되지만 공고문에 "서울"도 "한식"도 없다.

> **자격 여부와 텍스트 유사도의 상관이 약하다.** 청킹이나 하이브리드로
> 162위를 10위로 올릴 수 없다. 끌어올릴 근거가 문서에 없기 때문이다.
> → 검색은 후보를 고르는 일이 아니라 순서를 정하는 일로 역할을 재정의한다.

## 09-15 · 조건 추출 → 검색 0.947

`program_condition` 222건을 채워 정형 필터를 가동했다. 모델 `gpt-5.4-mini`.

| 지표 | 조건 없음 | 조건 있음 |
|---|---|---|
| Recall@30 (전국 제외) | 0.368 | **0.947** |
| 순위 중앙값 | 66위 | 16위 |
| 프로필당 후보 | 222건 | 4~54건 (평균 38) |
| SQL 오탈락 | — | **0건** |

정형 필터가 정답 19건을 하나도 떨어뜨리지 않았다. 남은 손실은 P07의 43위
하나이며 top-30 절단 탓이다. **후보 전량을 넘기면 Recall이 1.0이 된다.**

### 추출에서 잡은 오류

| 유형 | 사례 | 조치 |
|---|---|---|
| 시도 표기 불일치 | `[전남]` → "전남"(표준은 전남광주) | 별칭 정규화 |
| 시설 위치를 자격 제한으로 | "소담스퀘어 in 부산" → 부산 한정 | 제목 태그 규칙으로 대체 |
| 우대를 필수로 | "경상북도 소재 우대" → 경북 한정 | 프롬프트 보강 |
| 제외업종 오탐 | "체납 제외"를 보고 std_exclusion=true | SQL에서 제외 |

시도 판정은 **제목의 `[지역]` 태그로 결정론적 처리**하는 것이 가장 정확했다.
LLM 오류 4건, 태그 오류 1건(`124890`, 기업마당 데이터 자체 오류).

`std_exclusion`은 SQL 필터에서 뺐다. 제외업종 목록에 있어도 조건부로 허용하는
공고가 있어("부동산중개업 20% 이내 허용") 확실한 탈락이 아니다.

### 비용 구조

GMS 크레딧은 **1천 토큰당** 과금이다(호출당 아님). 공고 1건 추출에 약 150.
`gpt-5.4-mini`(14/1k)로 217건에 32,267 소모. 총 한도 100,000.
`gpt-5.4`(45/1k)로 전량 추출하면 약 10만이라 예산을 다 쓴다.

## 09-16 · 판정 범위 재정의 → 0.826

판정을 사업자 프로필로 대조 가능한 조건으로 한정하고 생년월일을 추가했다.

| 단계 | 정확도 |
|---|---|
| 판정 범위 한정 전 | 0.478 |
| 조건 방향·확인불가 규칙 | 0.522 |
| 판정 범위 한정 + 청크 대신 조건만 전달 | 0.556 |
| 모델 `gpt-5.4-mini` | 0.739 |
| "정보 없는 항목" 규칙 + 구조 정리 | **0.826** |

청크를 안 보내고 조건 목록만 넘기면서 요청당 토큰이 3분의 1로 줄었다
(약 3천 토큰, 42크레딧).

### 프롬프트 튜닝은 여기서 한계

0.826 이후 세 번 더 시도했으나 전부 하락했다.

- 적극요건 예외·절차 무시·업종 코드 규칙 추가 → 0.783
- 규칙 나열을 4단계 절차형으로 재작성 → 0.609

규칙이 늘수록 서로 충돌해 모델이 매번 다르게 조합한다. 절차형은
"해당해야만 통과" 판단을 과적용해 체납·휴폐업까지 unknown으로 밀어넣었다.

표본이 23건이라 한 건이 4.3%p다. 0.826과 0.783의 차이는 두 건이며
프롬프트 효과와 모델 변동을 구분할 수 없다.

## 09-16 · 후보 전량 검증 → 포함률 1.0

top-k 절단을 제거하고 SQL 통과분 전체를 LLM에 넘긴다. SQL 탈락 공고는
템플릿 사유를 만들며 LLM을 부르지 않는다(비용 0).

| | 이전 | 이후 |
|---|---|---|
| 후보 포함률 | 0.947 | **1.0** |
| 프로필당 후보 | 10건 | 4~54건 |
| 판정 정확도 | 0.826 (표본 23) | 0.800 (표본 75) |

**배치 처리가 필요했다.** 44건을 한 번에 요청하니 응답이 잘려 뒤쪽 22건이
누락됐다. 10건씩 나눠 `asyncio.gather`로 병렬 호출해 해결했다. 시스템
프롬프트가 반복돼 토큰이 30% 늘지만 누락이 사라진다.

같은 설정에서 0.800과 0.813이 번갈아 나온다. ±1건 변동이다.

## 09-16 · 조건 추출 품질 개선 → 0.803

프롬프트 튜닝이 0.80에서 멈춘 원인이 조건 데이터에 있다고 보고 추출을 고쳤다.

**`direction` 필드 추가** — 조건마다 `요건`(해당해야 통과) / `결격`(해당하면 탈락)을
명시한다. 검증 LLM이 매번 방향을 추론하다 틀리던 문제를 데이터로 옮겼다.
검증 규칙이 표 하나로 정리된다.

```
              대조 가능·충족   대조 가능·미충족   대조 불가
요건          통과             ineligible        unknown
결격          ineligible       통과              check_items
```

**표 축약** — 파싱 결과의 71%가 표인데 대부분 제외업종 목록·매출 기준표라
판정에 쓸모가 없다. 8행 넘는 표는 앞 3행만 남기고 기본 span 속성을 제거해
본문을 49%로 줄였다(`pipeline/text.py`).

**노이즈 필터** — 정형 필드 중복("상시근로자 5인 미만")과 서류 제출 요구
("소상공인확인서 제출")를 코드로 거른다. 프롬프트로도 막지만 모델이 자주
어겨 안전망이 필요했다. "사업자등록증상 소재지가 제주인 소상공인"처럼
실질 내용이 있으면 남긴다.

**서류 추출 제거** — `program_document`는 정확도가 낮아 수기로 채우기로 했다.

### 모델 선택 — gpt-4.1-mini

| 모델 | 전량 비용 | 우대/필수 구분 | 실패율 |
|---|---|---|---|
| **gpt-4.1-mini** | **7,700** | 프롬프트 보강 후 성공 | 0% |
| gpt-5-mini | 26,000 | 성공 | 25% (잘림·타임아웃) |
| gpt-5.4-mini | 34,000 | 성공 | 0% |

`gpt-4.1-mini`는 처음에 우대 조건을 `필수`로 뽑았다. 원문이 "(우선지원) ...
자격요건 중 한 가지 이상"이라 필수처럼 읽힌 것이다. 우대 신호어 목록과
"우선지원 블록 아래는 전부 우대" 규칙을 넣어 해결했다.

`gpt-5` 계열은 추론 모델이라 `max_completion_tokens`를 추론 토큰이 소진해
JSON을 못 내고, 타임아웃도 잦다.

### 결과

| 단계 | 정확도 |
|---|---|
| 전량 검증 구조 | 0.800 |
| direction 기반 검증 프롬프트 | 0.776 |
| 서류 노이즈 제거 | **0.803** |

`eligible → unknown` 오판이 3건에서 0건이 됐다. 서류 제출 요구가 `요건`으로
들어와 보류를 유발하던 것이다.
