### 추출 과정에서 잡은 오류 유형

| 유형 | 사례 | 조치 |
|---|---|---|
| 시도 표기 불일치 | `[전남]` → "전남"으로 출력, 표준은 "전남광주" | 별칭 정규화 |
| 시설 위치를 자격 제한으로 | "소담스퀘어 in 부산" → region=부산 | 제목 태그 규칙으로 대체 |
| 우대를 필수로 | "경상북도 소재 우대" → region=경북 | 프롬프트 보강 |
| 제외업종 오탐 | "체납 제외"를 보고 std_exclusion=true | SQL에서 제외, LLM 검증으로 이관 |

시도 판정은 결국 **제목의 `[지역]` 태그로 결정론적 처리**하는 것이 가장
정확했다. LLM이 틀린 경우 4건, 태그가 틀린 경우 1건(124890, 기업마당
데이터 자체 오류)이었다.

`std_exclusion`은 SQL 필터에서 뺐다. 제외업종 목록에 있어도 조건부로
허용하는 공고가 있어(125890: "부동산중개업 20% 이내 허용") "확실한 탈락"이
아니기 때문이다. 값은 계속 추출하되 LLM 검증의 근거로만 쓴다.

### 프롬프트 튜닝의 한계

0.826 이후 세 차례 더 시도했으나 모두 하락했다.

- 적극요건형 예외·절차 무시·업종 코드 체계 규칙 추가 → 0.783
- 규칙 나열을 4단계 절차형으로 재작성 → 0.609

규칙이 늘수록 서로 충돌해 모델이 매번 다르게 조합했다. 절차형은
"해당해야만 통과" 판단을 과적용해 체납·휴폐업까지 unknown으로 밀어넣었다.

**표본이 23건이라 한 건이 4.3%p다.** 0.826과 0.783의 차이는 두 건이며,
프롬프트 효과와 모델 변동을 구분하기 어렵다. 골든셋 확대가 필요하다.
